# tgnews — Telegram-бот «новостной редакции»

Бот, который собирает посты из публичных Telegram-каналов-доноров, переводит их
на русский в стиле заданного новостного канала (эмодзи-маркер + жирный лид +
нативные телеграм-цитаты) и выдаёт администраторам по запросу — командой `/get`.
Понравившиеся посты админы отправляют в общий чат отбора для доработки и
публикации. Никакой бесконечной ленты — только готовые к редактированию посты.

```
каналы-доноры (публичные TG-каналы)
        │  realtime + бэкфилл истории (Telethon, юзербот)
        ▼
┌─────────────────────────────────────────────┐
│  один Docker-контейнер                      │
│                                             │
│  worker (Telethon)          bot (aiogram)   │
│  ─ коллектор 15+ каналов    ─ /get [N]      │
│  ─ фильтры: медиа, форварды, ─ карточки     │
│    чёрный список, дедуп       модерации     │
│  ─ рефреш метрик/подписок   ─ перевод (LLM) │
│  ─ релей медиа в канал      ─ чат отбора    │
│    Q Relay (#Q<qid>)                        │
└─────────────────────────────────────────────┘
        │                                  ▲
        │ file_id relay (без перезаливки)  │ /get
        ▼                                  │
   бот @your_bot  ────── посты ─────── админы в личке
                                          │ кнопки
                                          ▼
                              чат «отбор» (общий, для доработки)
```

## Как это работает

1. **Сбор.** Юзербот (твой Telegram-аккаунт, Telethon) слушает каналы из списка в
   реальном времени и добирает последние посты при старте. Фильтры при сборе:
   посты без текста, репосты чужих каналов, чёрный список (спорт-результаты,
   реклама, лайфстайл), дедуп Jaccard-фингерпринтом.
2. **Ранжирование.** `/get` выдаёт топ из окна 24 часа по нормированным метрикам:
   *просмотры относительно аудитории канала* × *вовлечённость (реакции/просмотры)*
   × *свежесть* (полураспад 12ч). Мелкий канал с жирным постом поднимается выше
   гигантов. Метрики (просмотры/реакции) воркер перечитывает каждые 10 минут —
   пост, собранный в момент публикации, не остаётся с нулём.
3. **Перевод.** При `/get` топ-N постов прогоняется через LLM: чистый
   «перевод + форматирование», без пересказа. Прямая речь — только прямой речью,
   оформляется нативной телеграм-цитатой (`<blockquote>`, длинные цитаты —
   сворачиваемые). Реклама и не-новости модель отбраковывает словом `SKIP`.
   Основная модель + автоматический фолбэк.
4. **Доставка.** Пост приходит админу в личку с ботом: медиа из первоисточника
   (без перезаливки, через file_id relay) + переведённый текст + через пустые
   строки голая ссылка на источник. Под постом карточка модерации:
   **[В отбор] [Отказ]**.
5. **Отбор.** «В отбор» копирует пост в общий чат (все админы + бот) с пометкой
   «Добавил: @admin» — там его дорабатывают и публикуют руками. Решения
   сохраняются, отклонённое не предлагается повторно.

## Что нужно

- VPS с Docker + Docker Compose (хватит 1 vCPU / 2 GB RAM)
- Telegram-аккаунт под юзербота (тот, на котором сканируешь QR при настройке)
- Бот: создай в [@BotFather](https://t.me/BotFather), забери токен
- Ключ доступа к LLM-провайдеру (OpenAI-совместимый `/responses` или
  `/chat/completions`) — по умолчанию настроен [opencode](https://opencode.ai)

## Установка

```bash
git clone https://github.com/izislesar/tgnews.git && cd tgnews
cp .env.example .env && nano .env   # заполнить (см. таблицу ниже)
docker compose build
```

Логин юзербота (один раз): команда покажет QR — отсканируй его телефоном,
где залогинен нужный аккаунт (Telegram → Настройки → Устройства → Привязать
устройство). Сессия сохранится в `data/` и переживёт перезапуски.

```bash
docker compose run --rm -it app python -m app.qrlogin
```

Запуск:

```bash
docker compose up -d
docker compose logs -f
```

При старте воркер сам создаст скрытый канал-релей **Q Relay** (для передачи
медиа боту), подпишется на каналы из `channels.txt`, доберёт историю и начнёт
копить метрики.

### Настройка чата отбора

Создай обычный групповой чат, добавь туда бота и всех админов, затем напиши
**внутри этого чата**:

```
/set_approval_chat
```

Готово — одобренные посты будут падать туда. Либо пропиши `APPROVAL_CHAT_ID`
в `.env`.

## Конфигурация (.env)

| Переменная | По умолчанию | Что это |
|---|---|---|
| `OPENCODE_API_KEY` | — | ключ LLM-провайдера (обязательно) |
| `OPENCODE_MODEL` | `muse-spark-1.3-contributor` | основная модель |
| `OPENCODE_MODEL_FALLBACK` | `glm-5.3-flash` | фолбэк, если основная недоступна |
| `OPENCODE_BASE` | `https://opencode.ai/inference/go/v1` | базовый URL (OpenAI-совместимый) |
| `BOT_TOKEN` | — | токен бота из BotFather (обязательно) |
| `BOT_USERNAME` | `lalsdjasdljkbot` | username бота (для релея медиа) |
| `ADMIN_IDS` | — | Telegram user_id админов через запятую (обязательно) |
| `APPROVAL_CHAT_ID` | из `/set_approval_chat` | чат отбора (можно не задавать) |
| `API_ID` / `API_HASH` | ключи Telegram Desktop | можно не задавать |
| `SESSION_PATH` | `/data/session` | файл сессии юзербота |
| `GET_N` / `GET_MAX` | `5` / `10` | постов по /get по умолчанию и потолок |
| `GET_CANDIDATES` | `15` | размер шорт-листа для перевода |
| `WINDOW_H` | `24` | окно отбора /get, часов |
| `DEDUP_WINDOW_H` | `= WINDOW_H` | окно дедупа, часов (независимое) |
| `FRESH_HALF` | `12` | полураспад свежести, часов |
| `ERATE_W` | `10` | вес вовлечённости (реакции/просмотры) |
| `VRATE_EXP` | `0.5` | степень нормировки просмотров на аудиторию |
| `LINK_GAP` | `5` | пустых строк между постом и ссылкой на источник |
| `DEDUP_JACCARD` | `0.6` | порог дедупа по фингерпринту |
| `METRICS_PERIOD` | `600` | период рефреша просмотров/реакций, сек |
| `SUBS_PERIOD` | `21600` | период рефреша аудитории каналов, сек |
| `MEDIA_WAIT_S` | `120` | сколько ждать релей медиа при /get |
| `TZ` | `Europe/Berlin` | часовой пояс контейнера |

## Команды бота

| Команда | Что делает |
|---|---|
| `/get [N]` | выдать посты: топ за 24ч, этому админу раньше не показанные |
| `/add_channel @user` | добавить канал-донор (публичный) |
| `/delete_channel @user` | убрать канал из работы |
| `/list_channels` | список доноров |
| `/stats` | очередь + таблица источников: всего/скип/дубли/выдано/в отбор |
| `/set_approval_chat` | назначить текущий чат чатом отбора |
| `/help` | справка |

Команды работают только у админов из `ADMIN_IDS` и только в личке с ботом
(кроме `/set_approval_chat`).

## Стиль публикаций и фильтры

- **`prompt.txt`** — системный промпт LLM: правила перевода, палитра
  эмодзи-маркеров, формат цитат, правила SKIP. Форматирование постов задаётся
  здесь же. После правки — `docker compose restart`.
- **`app/worker.py` → `BLACKLIST`** — чёрный список тем (регэкспы, проверяются
  при сборе, ноль токенов). По умолчанию: спорт-результаты, реклама/промо,
  гороскопы/лайфстайл. Крипта и знаменитости-ньюсмейкеры — публикуются.
- **`channels.txt`** — стартовый список доноров, сидируется в БД при первом
  запуске; дальше список живёт в БД и управляется командами бота.

## Ограничения (честно)

- Доноры — только публичные каналы; юзербот должен иметь доступ
  (каналы ботоподпиской не читаются).
- Кросс-языковой дедуп (та же новость с арабского и английского доноров)
  не ловится — Jaccard работает внутри одного языка.
- Юзербот на личном аккаунте: чтение каналов и постинг в релей — обычная
  активность, но аккаунт — единая точка отказа. Признаки логаута в логах:
  `AuthKeyDuplicated` / `Unauthorized`.
- Перевод идёт последовательно: `/get` с медиа занимает до пары минут.

## Частые проблемы

| Симптом | Причина / решение |
|---|---|
| `Сессия worker'а не авторизована` | пройти `python -m app.qrlogin` заново |
| `BOT_TOKEN пуст` / `ADMIN_IDS пуст` | заполнить `.env`, `docker compose up -d --force-recreate` |
| Посты без медиа, хотя в доноре картинка | релей не готов: проверь логи `[relay]`, канал Q Relay существует, бот — админ |
| Все посты `dead` | слишком строгий промпт: модель уходит в SKIP — смягчи правила в `prompt.txt` |
| В выдаче мусор не по теме | дополни `BLACKLIST` в `app/worker.py` и/или правило 8 в `prompt.txt` |
